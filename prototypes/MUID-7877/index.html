Assumptions

  • No PRD, designs or analytics events were provided, so no analytics are shown. Screens and copy are placeholders.
  • Registered and unregistered emails see the same confirmation message and the same code screen. The demo inbox above is a prototype aid and would not exist in the product.
  • The confirmation message and code entry share one screen.
  • Email check: a basic format check only (invalid format shows an inline error).
  • Codes expire after 10 minutes. Expired codes show an error and prompt a new request.
  • After 3 wrong codes, entry is locked and the user taps "Request a new code". The same option is available any time via "Request a new one", for example when no code arrives.
  • A new code makes the previous code invalid and resets the 3-attempt count. There is no limit on new requests.
  • Unregistered emails never receive a code, so entering any code counts as wrong, following the same 3-attempt rule.
  • Leaving mid-flow (back to log in or using a different email) discards progress. The user must restart from the email step.
  • Password rules: at least 8 characters, must match confirmation, must differ from the old password (demo old password: OldPass123!).
  • After saving, the user returns to log in signed out. Ending other sessions is not shown.
  • Email delivery failures and delays are not simulated.
  • Touch and desktop are both supported, since the platform is not confirmed.
