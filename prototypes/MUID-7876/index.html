    Assumptions

    • Demo sign-up accepts any values; defaults shown on the form are alex@example.com / demo1234. There is no real authentication or backend.
    • The checklist has 3 items: Create first project (required), Add first task (required), Connect a tool (optional, simulated). The spec leaves the other checklist tasks open.
    • Teammate invitation is not in this prototype because it is an open question.
    • Team administrators follow the same path as other roles; only the copy changes. A separate admin path is not defined.
    • "Unusual" role or goal means choosing "Other"; it gets a generic default checklist and sample names.
    • For a user with an existing project, the project item is pre-completed and adding a task to that project counts as activation.
    • The checklist stays visible after activation, in a completed state. Remaining optional items show as dismissed.
    • Abandonment is simulated with a button, and a reload mid-onboarding also shows the resume prompt. Progress is saved in this browser's local storage, or in memory if storage is blocked.
    • Error flows are not defined. Only basic empty-field validation is shown.
    • "Preferred way of working" has no event of its own, so it is recorded as detail on goal_selected.
    • "Skip optional steps" (top right) marks the optional Connect step as skipped. Required steps are never hidden.
    • Tooltips for the first project and first task are shown once and not repeated.
